# 网站页面和组件详情页结构说明

状态：**业务前端尚未实现**。目前可用的页面是 `/docs` 和 `/redoc`；下列路由为后续开发约定。

## 应用外壳

左侧导航包含总览、仿真、处方、批次、设备、报警与追溯。顶部常驻虚拟时钟、自动运行状态、倍率、连接状态和全局控制；页面内明确展示是否为匿名演示数据。

| 规划路由 | 页面内容 | 当前后端数据 |
|---|---|---|
| `/overview` | 总量、产出、报警、设备利用率 | `GET /api/v1/dashboard` |
| `/simulation` | 流程示意、运行队列、工位占用 | `GET /api/v1/simulation`、WebSocket |
| `/prescriptions` | 处方列表、筛选、录入、审核 | `/api/v1/prescriptions` |
| `/prescriptions/:id` | 匿名信息、药组、工艺、审核记录 | `GET /api/v1/prescriptions/{id}` |
| `/batches` | 状态、进度、等待原因 | `GET /api/v1/batches` |
| `/batches/:id` | 工序、追溯码、温度、暂停/取消 | 批次、telemetry、events |
| `/devices` | 类型、占用、故障、启停 | `/api/v1/devices` |
| `/alarms` | 活跃/已解决、确认、关联定位 | `/api/v1/alarms` |
| `/trace/:code` | 处方与批次追溯、事件分页 | `GET /api/v1/trace/{code}` |

## 仿真工作台

顶部放全局控制；主体展示从调剂到清洗的工序和设备，侧栏展示选中批次；下部展示队列、温度与事件。先煎和二煎节点是否存在由批次 `steps` 决定，后下通过投料事件表示，不能固定所有处方的节点数量。

## 详情页结构

批次详情包含：摘要（追溯码、状态、处方）、工艺（水量计划与参数）、工序时间轴、当前设备与等待原因、曲线、事件、可执行动作。全部完成需同时看到清洗结束，成品已配发与批次完成分别显示。

未来组件库详情页若有需要，采用“用途、运行示例、输入属性、交互事件、状态案例、无障碍、变更记录”结构；组件库不属于当前后端交付。

## 路由与错误

列表筛选和分页写入查询参数，详情使用稳定 ID。后端返回 404 时显示资源不存在；409 显示操作受限原因；422 展示参数错误。断线后先重新拉取快照，再继续订阅推送；操作提交以 HTTP 返回结果为准。
