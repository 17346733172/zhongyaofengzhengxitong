# 网站页面和组件详情页结构说明

状态：**部分已实现**。`frontend/` 已实现总览、仿真工作台、设备分类及类型页面、处方、批次和追溯路由；报警独立页面仍为规划。`/docs` 与 `/redoc` 由后端提供。

## 应用外壳

左侧导航包含总览、仿真工作台、设备分类、处方和批次；报警内嵌在仿真工作台，追溯从批次进入。顶部常驻当前北京时间、真实计时运行状态、连接状态；工作区上方提供开始、暂停与生成演示数据，不提供倍率输入和手动推进；页面内明确展示是否为匿名演示数据。

| 路由 | 页面内容 | 当前后端数据 | 状态 |
|---|---|---|---|
| `/overview` | 总量、产出、报警、设备类型入口 | `GET /api/v1/dashboard` | 已实现 |
| `/devices` | 设备类型入口及各类数量、状态汇总 | `GET /api/v1/dashboard` | 已实现 |
| `/devices/:kind` | 单类设备卡片、利用率和选中详情 | dashboard、仿真快照 | 已实现 |
| `/simulation` | 流程示意、运行队列、工位占用 | `GET /api/v1/simulation`、WebSocket | 已实现 |
| `/prescriptions` | 处方列表、筛选、录入、审核 | `GET/POST /api/v1/prescriptions` | 已实现 |
| `/prescriptions/:id` | 匿名信息、药组、工艺、审核记录 | `GET /api/v1/prescriptions/{id}` | 已实现 |
| `/batches` | 状态、进度、等待原因 | `GET /api/v1/batches` | 已实现 |
| `/batches/:id` | 工序、追溯码、温度、暂停/取消 | 批次、`/telemetry` | 已实现 |
| `/trace/:code` | 处方与批次追溯、事件分页 | `GET /api/v1/trace/{code}` | 已实现 |

总览只保留设备类型入口；每种类型在独立页面展示，例如 `/devices/pot` 只显示煎药锅，`/devices/soaking` 只显示浸泡工位。类型页可返回分类目录，直接刷新仍保留当前类型；未知类型明确提示不存在。设备故障、修复和启停操作仍在仿真工作台，报警独立页面为规划。

## 仿真工作台

工作区上方提供全局控制与演示数据生成入口（1–50 批，默认 5 批）。无批次时明确提示生成数据或录入审核处方，再开始真实计时仿真。工作台依次显示活跃报警、批次队列、设备卡片、选中设备操作和报警记录；批次进度、温度与工序明细可进入详情页查看。先煎和二煎节点是否存在由批次 `steps` 决定，后下通过投料事件表示，不能固定所有处方的节点数量。流程拓扑及选中批次侧栏仍为规划。

## 详情页结构

批次详情包含：摘要（追溯码、状态、处方）、工艺（水量计划与参数）、工序时间轴、当前设备与等待原因、曲线、事件、可执行动作。全部完成需同时看到清洗结束，成品已配发与批次完成分别显示。

未来组件库详情页若有需要，采用“用途、运行示例、输入属性、交互事件、状态案例、无障碍、变更记录”结构；组件库不属于当前后端交付。

## 路由与错误

列表筛选和分页写入查询参数，详情使用稳定 ID。后端返回 404 时显示资源不存在；409 显示操作受限原因；422 展示参数错误。断线后先重新拉取快照，再继续订阅推送；操作提交以 HTTP 返回结果为准。
