# 项目定位、产品目标和功能范围

## 定位

建设用于教学演示、流程理解及产线排队实验的中药煎药仿真平台。当前先提供后端，后续前端直接使用统一 API，避免在页面中重复实现工艺和状态规则。

## 参考依据

参考[厚达智能北京本草方源煎药中心应用案例](http://www.houdar.com/prodetail.html?appid=1.2)，于 2026-11-02 读取。页面通过其公开案例接口加载内容，标题为“北京本草方源煎药中心应用案例”。

案例覆盖智能接方、饮片调剂、加水浸泡、个性化煎煮、自动包装配发和锅具清洗，强调全过程追溯。项目据此抽象业务顺序。软件工序耗时、默认资源数量、水量计算、曲线和故障逻辑由本项目设定；未获得厂商控制协议或实际设备参数。

## 用户与任务

学习者按现实时间观察流程；教学人员通过暂停、故障、设备数量和处方优先级展示排队变化；开发者利用状态、事件和追溯接口构建可视化。

## 当前功能范围

| 模块 | 能力 | 边界 |
|---|---|---|
| 处方 | 匿名录入、人工审核、驳回 | 不执行配伍、禁忌或临床剂量判断 |
| 工艺 | 常规、先煎、后下、包煎、可选二煎 | 分组容器和包煎袋内部不建模 |
| 调度 | 优先级、FIFO、独占工位、锅容量 | 不支持抢占与随机运输路径 |
| 时钟 | 固定真实时间 1 倍速、暂停 | 暂停和服务离线期间不累计工序用时 |
| 异常 | 手工故障、修复、报警确认 | 不模拟真实传感器故障机理 |
| 追溯 | 处方、批次、事件、温度采样 | 非真实生产质量证明 |

## 工艺约定

1. 处方审核通过后创建批次；同一处方不能重复创建批次。
2. 每批次保留一口锅，初次调剂时取得，正常结束或取消清洗完成后归还。
3. 先煎组在常规药组入锅前处理；常规药组先独立浸泡，容器细节省略。先煎阶段直接采用目标温度插值，未独立建模升温持温。
4. 后下只在一煎剩余指定时长时触发一次事件；二煎不重复投料。包煎通过调剂标记表达。
5. 二煎为零时跳过对应阶段；有二煎时一煎液先滤出暂存，二煎后合液。
6. 复核和成品质检自动模拟通过；产品配发后还需倒渣清洗，批次才最终完成。
7. 取消未取得锅的批次可立即结束；生产中取消需等待清洗。已配发的成品不允许取消。

## 默认工序用时

以下为用户指定的演示用时，每批次、每次执行分别计时，不是厂商参数或药学建议。

| 工序 | 用时（分钟） | 接口用时（秒） |
|---|---:|---:|
| 调剂 | 10 | 600 |
| 复核 | 5 | 300 |
| 输送 | 5 | 300 |
| 加水 | 3 | 180 |
| 浸泡 | 5 | 300 |
| 煎煮 | 15 | 900 |
| 过滤 | 3 | 180 |
| 包装 | 5 | 300 |
| 贴标 | 5 | 300 |
| 质检 | 3 | 180 |
| 配发 | 3 | 180 |
| 倒渣 | 2 | 120 |
| 清洗 | 3 | 180 |

先煎、一煎及二煎默认各 15 分钟；额外升温默认 0，温度变化并入煎煮。重复输送、加水、过滤均按每次计时。常规单煎不含等待总用时为 67 分钟；默认二煎开启时为 88 分钟。历史批次的计划与追溯不回写。

## 数据与验收

不输入真实患者身份或联系方式。每个批次包含匿名处方、追溯码、工序、温度、锅具、占用设备和事件。验收要求：可由干净数据库创建场景、完整运行、注入故障、修复继续、查询追溯；重启后数据一致且自动时钟暂停；文档列出的接口可用。
