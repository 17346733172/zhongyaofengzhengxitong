# 组件开发、样式、依赖和无障碍规范

状态：**前端规划**。尚无前端组件包、npm 项目或可发布的组件库。本文件用于后续实现，后端接口已可供对接。

## 组件边界

将通用展示与业务动作分开。`StatusBadge` 只展示状态；`SimulationControls` 负责全局时钟；`BatchTimeline` 负责工序历史；`DeviceCard` 展示设备与故障；页面负责加载数据和提交操作。业务状态以后端为准，不在前端自行递增工序。

| 拟建组件 | 输入 | 主要行为 |
|---|---|---|
| SimulationControls | clock、连接状态 | start / pause / step |
| BatchTimeline | steps、current_stage、waiting_reason | 节点选择、事件查看 |
| DeviceCard | device、alarm | 故障、修复、停用、启用 |
| PrescriptionForm | herbs、recipe | 字段校验、保存、审核 |
| TemperatureChart | telemetry.point 列表 | 虚拟时间缩放与悬浮读数 |
| TracePanel | batch、prescription、events | 分页读取完整轨迹 |

## 接口和依赖

前端框架待确定。确定后统一 TypeScript、请求封装和设计变量；只引入确有需要的图表或组件依赖。建议根据 `/openapi.json` 生成请求类型，再为响应字段补充类型与校验。WebSocket 是快照通道，历史事件必须使用事件接口补齐。

前端来源默认是 `http://localhost:5173` 或 `http://127.0.0.1:5173`；其他端口或 HTTPS 来源需配置后端环境变量。配置了 API Key 时，由连接后的首条 WebSocket 消息提交密钥，不放在 URL 中。当前密钥是演示级共享访问控制，不作为未来账户系统。

## 样式约定

共享颜色与间距取自 `DESIGN.md`；组件不得随意定义不同状态颜色。数字明确标注单位，时间统一标注“虚拟秒/分钟”，避免与真实记录时间混淆。表格列保留稳定顺序，空值用“尚未分配”等明确文字。

## 无障碍和状态

- 使用语义按钮、表格、标题和 label；所有操作可通过键盘完成。
- 状态同时提供文字，曲线提供数值表或摘要。
- 使用可见焦点和满足对比度的文字；尊重减少动态效果的系统设置。
- 动态数据不自动移动焦点，报警摘要可使用适度的实时提示。
- 覆盖加载、空数据、失败、断线、权限不足和取消后清洗状态。
- 表单错误同时显示字段与原因；禁止只靠红色边框表达错误。

## 后续验收

组件落地后检查正常、等待、暂停、故障和完成状态；验证窄屏、键盘和断线恢复。未实现组件在登记表中保持“规划”，不得标记为已发布。
